# person-simulator

把**预清洗的双人聊天**转换为指定人物的、可独立上传到网页版 AI 的角色扮演 Markdown。

流程：严格解析 → 会话/预算切分 → 可配置模型 API（或离线 Mock）→ 证据驱动建模 → `person_simulation.md`。不做 GUI、聊天软件解析器、模型训练、向量数据库或程序内实时聊天。

## 安装

Windows PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.lock
```

macOS / Linux：

```bash
python -m venv .venv
./.venv/bin/python -m pip install -r requirements-dev.lock
```

开发安装也可用 `.\.venv\Scripts\python.exe -m pip install -e ".[dev]"`。

## 输入格式

```text
A: 早，今天出门吗？
B: 看情况。
  如果不下雨就去。
```

- 支持 `A:`、`A：`、`[ISO8601] A: 文本`。
- 续行必须以两个空格开头；只由两个空格组成的行表示正文空行。
- `--target` 必须精确匹配 `--speaker-a` 或 `--speaker-b`，不按文件顺序猜身份。

完整规则见 `docs/input-format.md`。

## 常用命令

```powershell
# 校验
python -m person_simulator validate --input examples/sample_chat.txt --target A

# 离线查看切分与预算（不联网、不打印正文）
python -m person_simulator plan --input examples/sample_chat.txt --target A

# Mock 全流程（默认 evidence 模式）
python -m person_simulator build --input examples/sample_chat.txt --target A --mode mock --out runs

# Whole-chat：整段原文直接生成 system_prompt.md / person_simulation.md
python -m person_simulator build --input data/chat.txt --target A --strategy whole --out runs

# 自动按上下文预算选择 whole 或 evidence
python -m person_simulator build --input data/chat.txt --target A --strategy auto --out runs

# 只分析前 50 条做 pilot
python -m person_simulator build --input data/chat.txt --target A --strategy whole --limit-messages 50 --out runs

# 模拟：A=压缩 system prompt；B=完整原文
python -m person_simulator simulate --run runs/<run-id> --message "在吗？"
python -m person_simulator simulate --input data/chat.txt --speaker-a "TARGET" --speaker-b "OTHER" --target "TARGET" --message "在吗？"

# 失败后从检查点恢复（参数必须与 run 指纹一致）
python -m person_simulator resume --run runs/<run-id>

# 另存一份导出，不覆盖已有文件
python -m person_simulator render --run runs/<run-id> --out exports/demo

# 生成人工评估包
python -m person_simulator eval prepare --input data/chat.txt --target A --out eval_runs/demo

# 汇总人工回答与评分
python -m person_simulator eval score --bundle eval_runs/demo --responses eval_runs/demo/responses.jsonl --ratings eval_runs/demo/ratings.csv
```

## 真实 API

```powershell
$env:PSIM_API_KEY = "YOUR_API_KEY"
python -m person_simulator plan --input data/chat.txt --target A --config config.toml
python -m person_simulator build --input data/chat.txt --target A --mode api --config config.toml --out runs
```

配置示例见 `config.example.toml`。Key 只从 `PSIM_API_KEY` 读取，不写入 TOML、命令行、manifest 或日志。

第一版仅支持 **HTTPS + Bearer Key + 非流式 `POST /chat/completions` + `choices[0].message.content`**。不发送 tools、streaming、thinking、response_format 或 temperature，除非显式配置。不保证跨服务商兼容，也不保证重试时 exactly-once。

## 已知导出格式转换

如果已有特定格式的微信 Markdown 导出（`## 日期` + `**[时间] 说话人**` + 正文），可用本地助手转换：

```powershell
python tools\convert_wechat_md.py "D:\export.md" --out data\chat.txt --speaker-a "TARGET" --speaker-b "OTHER"
```

它只针对该导出形状，不是通用微信解析器；不会打印正文，不读取 Key，产物在 `.gitignore` 的 `data/` 下。

## 真实状态与限制

- Mock E2E：A/B、180 条长文本与断点恢复已实跑。
- 真实 API：Whole-chat 已用 DeepSeek 实跑；evidence 模式仍是 **not_verified**，需要配置 Key 并明确授权后验收。
- 人物模拟质量：**not_evaluated**，需要真实材料、独立留出、人工回答与评分；Mock 不能证明相似度。
- 覆盖 `coverage=1` 只表示原文切分/处理完整，不表示语义理解正确。
