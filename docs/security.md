# 安全模型

## 目标

在所有者托管、第三方体验的场景下：

- 人物档案、运行时提示词、原始聊天和 API Key 不离开所有者控制的机器（模型请求除外）。
- 第三方只能通过受控入口对话，不能下载完整档案。
- 邀请可过期、可撤销、可限制会话数。
- 输出检查降低直接身份信息和提示词泄露风险。
- 默认不把服务暴露到未显式允许的网络。

## 信任边界

| 边界 | 信任 | 说明 |
|---|---|---|
| 所有者机器/账户 | 信任 | 运行服务、持有 Key 和 run |
| 第三方浏览器/客户端 | 不信任 | 只应获得邀请和对话 |
| 模型服务商 | 外部处理者 | 会看到提示词与对话 |
| 隧道/反向代理 | 外部传输 | 可能看到流量；不要转发管理员端口 |
| 公共互联网 | 不信任 | 必须 HTTPS + 令牌 + 限额 |

## 主要控制

- **默认 loopback**：`127.0.0.1`；非 loopback 必须显式 `allow_lan`。
- **双监听器**：公开端口没有 `/admin/*`；管理员端口只绑定 loopback，不经过隧道。
- **管理员令牌**：只从 `PSIM_ADMIN_TOKEN` 或 `--admin-token-file` 读取，不接受命令行明文。
- **邀请**：加密文件 + 令牌哈希 + 过期 + 撤销 + 每邀请/全局会话上限。
- **会话**：随机 ID、Cookie `HttpOnly`/`SameSite=Strict`、TTL、空闲超时、轮数/输入/速率限制。
- **Host/Origin 校验**：拒绝未知 Host 和跨源请求，降低 DNS rebinding/CSRF 风险。
- **不暴露文件**：公开端口只提供打包的静态 UI 和 JSON API；不把 run 目录作为静态根。
- **输出检查**：直接身份信息脱敏、提示词长片段/内部标记/逐字复述阻断；失败不写入历史。
- **无静默降级**：Provider 失败返回错误，不自动改用 Mock。
- **日志脱敏**：不记录 Key、令牌、完整提示词或聊天正文。

## 已知限制

- 输出检查无法识别所有姓名、地址、暗示性身份信息或改写后的复述。
- 提示注入不能靠提示词彻底阻止；服务没有文件/工具权限，但模型仍可能被诱导输出已知上下文。
- C 可以截图、转发对话或分享邀请令牌；只能靠过期、撤销和限额降低影响。
- 模型服务商和隧道提供方的可见性无法由本项目消除。
- 会话和邀请默认只在内存中；崩溃/重启会丢失，也可能在核心转储/内存转储中留下内容。
- 管理员令牌如果泄露，攻击者可在本机访问管理员端口；应使用文件/环境变量并限制本机账户权限。
- 本项目没有经过独立安全审计；不要把它当作高价值秘密的强隔离边界。

## 安全报告

请通过仓库 Issue 私下联系维护者（仓库建立后补充安全联系方式）。报告时不要粘贴真实聊天、人物档案、API Key、邀请令牌或可识别个人的信息。

## 发布前检查

- `git diff --cached` 不含真实数据/Key/邀请文件。
- 构建产物不含 `data/`、`runs/`、`exports/`、`eval_runs/`、`config.toml`、`.env`。
- 默认配置仍只监听 loopback。
- 管理员路由不在公开监听器。
- 输出检查、会话删除、跨邀请隔离测试通过。
- README 不包含“绝对隐私”“无法推断”等超出能力的承诺。
