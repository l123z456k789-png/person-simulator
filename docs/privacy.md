# 隐私与数据处理

## 数据分类

| 数据 | 位置 | 谁能读取 |
|---|---|---|
| 原始聊天 | 所有者 `data/` 或指定输入路径 | 所有者、本机进程 |
| 完整人物档案 `persona.json` / `person_simulation.md` | run 目录 | 所有者 |
| 运行时提示词 `system_prompt.md` | run 目录 + 所有者进程内存 | 所有者、模型服务商（请求时） |
| API Key | `PSIM_API_KEY` 环境变量 | 所有者、本机进程 |
| 邀请凭证 `invite.psim` | 所有者发给 C 的文件 | 所有者、C（口令持有者） |
| 邀请令牌哈希 | 所有者服务内存 | 所有者进程 |
| 会话消息 | 所有者服务内存 | 所有者进程、C 的浏览器/客户端 |
| 普通日志 | 默认不记录正文 | 所有者 |

## 数据流

```text
原始聊天 -> 所有者建模 -> run（本地）
run -> 运行时提示词 -> 所有者服务 -> 模型服务商
C 的消息 -> 所有者服务 -> 模型服务商
模型回复 -> 输出检查 -> C
```

## 外部处理者

- **模型服务商**：会收到人物提示词、对话历史和当前消息。无法避免；使用前必须告知 C。
- **隧道/反向代理**：Tailscale 提供设备间加密；Cloudflare Tunnel 等会终止 TLS，提供方可能看到流量。
- **C 的远程 agent**：会看到对话内容，但不会收到人物提示词；如果 agent 自己调用模型，对话还会进入该 agent 的模型服务商。
- **操作系统/云同步**：run 和邀请文件可能被 OneDrive 等同步；所有者应自行决定存放位置。

## 日志

默认只输出命令结果和错误摘要：

- 不记录 API Key、邀请令牌、管理员令牌、完整提示词或聊天正文。
- HTTP 服务默认不打印请求日志；详细模式也只打印方法/路径/状态，不打印查询字符串和 Cookie。
- 错误信息不包含密钥或完整聊天；模型服务错误对第三方只返回概括信息。

## 邀请与加密

- `invite.psim` 只含 endpoint、令牌、有效期、备注、可选指纹/限额。
- 使用 PBKDF2-HMAC-SHA256 + Fernet 加密；口令不写入文件/日志/TOML。
- 如果口令与邀请文件走同一渠道，加密只防静态窥探；不能防拿到整条消息的人。
- 令牌是能力凭证；C 可以转发给他人。所有者应设置有效期、会话上限，并在需要时撤销。
- 服务重启会清空内存邀请；重启后需要重新创建。

## 会话删除

- 第三方结束会话：状态变为 ended，消息内容立即清空，保留短暂元数据墓碑。
- TTL/空闲过期：同样清空消息内容。
- 管理员删除：立即移除会话。
- 服务停止：所有内存会话消失。
- run 目录和导出文件不会因为结束会话而删除；所有者需自行管理 `runs/`、`exports/`、`eval_runs/`。

## 构建导出时的直接身份信息

`build` / `render` 默认会扫描 `person_simulation.md` 和 `system_prompt.md` 中的手机号、身份证号、邮箱、座机、银行卡，并在 `build_report.md` 中写入分类计数；警告不回显具体内容。

- `--redact-pii`：把导出文件中的命中项替换为 `[已隐藏]`。这是有损操作，会改变原话示例；运行目录里的 `messages.jsonl`、`persona.json` 仍保留原始内容。
- `--privacy-strict`：发现命中项时拒绝写入正式导出文件，run 会标记为未完成。
- 姓名、地址、暗示性身份信息不在正则覆盖范围内；需要人工检查或使用运行时的 `simulation.blocked_terms` 词表。
- 这些选项不能替代对原始聊天的授权、清理和分享前检查。

## 不能承诺的事

- 不能阻止 C 从语言风格、行为模式和历史细节推断人物特征。
- 不能阻止 C 截图、转发对话或把邀请令牌给别人。
- 不能阻止模型服务商按自己的条款处理请求。
- 不能保证所有姓名、地址、暗示性身份信息都能被正则或词表识别。
- 不能绝对阻止提示注入或改写后的复述；输出检查是尽力而为的第二道防线。

## 公开仓库卫生

以下内容不得提交：

- `data/`、`runs/`、`exports/`、`eval_runs/`
- `config.toml`、`.env*`、任何真实 Key
- `*.psim` 邀请文件、会话日志
- 真实人物昵称、聊天摘录、可识别个人的评估材料

`.gitignore` 已覆盖上述目录；提交前仍需检查 `git diff --cached` 与敏感信息。
