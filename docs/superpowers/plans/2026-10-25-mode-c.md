# Mode C 第三方模拟体验 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不改变模式 A 行为的前提下，新增去中心化的所有者托管模式 C：A 在本机运行模拟服务，C 通过加密邀请用客户端或浏览器聊天，人物档案不离开 A。

**Architecture:** 运行时从现有 evidence/whole run 严格派生 `RuntimePersonaV1`；HTTP 服务复用现有 Provider、RequestRunner、预算与错误分类；邀请是加密凭证，不是人物档案；会话只在内存中，支持限额、TTL、撤销与删除；输出检查覆盖直接身份信息、提示词泄露和逐字复述。

**Tech Stack:** Python 3.11+、Pydantic 2、httpx、标准库 `http.server`/`ssl`/`threading`、`cryptography`（邀请加密）、pytest。

**Spec:** `docs/superpowers/specs/2026-10-25-mode-c-design.md`

## Global Constraints

- Python `>=3.11`；当前验证环境 Python 3.12.10 / Windows / Git 2.55。
- 模式 A 的 `build`、`resume`、`render`、`eval` 行为不得改变；现有 83 个测试必须继续通过。
- 测试不得依赖真实聊天、真实人物档案、真实 API Key 或个人绝对路径；使用 `tmp_path` 与合成样例。
- CI 不得调用真实模型 API。
- 不把 `data/`、`runs/`、`exports/`、`eval_runs/`、`config.toml`、`.env` 或密钥提交到 Git。
- 默认只监听 `127.0.0.1`；局域网必须显式开启；公网通过隧道/反向代理提供 HTTPS，不默认裸 HTTP。
- 任何第三方接口都不得返回 `person_simulation.md`、`system_prompt.md`、`persona.json` 或原始聊天。
- 模型失败、输出检查失败、会话结束时不得伪造成功回复，不得静默回退 Mock。
- 运行时、邀请、会话的数据契约必须版本化；未知版本明确拒绝。
- 新增依赖只允许 `cryptography`（邀请加密）；不引入 Web 框架或数据库。
- 每个任务结束前运行相关测试并提交；提交前检查 `git diff --cached` 与敏感信息。
- 版本目标 0.2.0；许可证 MIT。

## Review Focus

1. **失败/不完整的 run 被当成有效人物加载**：`serve` 必须拒绝 `status != complete`、分析/导出未完成、来源哈希不一致、缺少 `persona.json`/`system_prompt.md` 的目录；错误必须可操作。
2. **模型回复直接输出手机号、身份证、邮箱、姓名/地址**：输出检查必须实际脱敏或拒绝，不能只靠提示词；会话不得保存未脱敏原文。
3. **提示注入或连续追问套出 system prompt/人物档案/原始聊天**：固定安全提示 + 输出检查 + 无文件/工具访问；测试必须覆盖直接索取、角色反转、伪造管理员、长片段泄露。
4. **跨邀请/跨会话访问**：一个邀请的令牌或会话不能读取另一个邀请的会话；管理员接口只允许 loopback + 管理员令牌；Host/Origin 校验必须生效。
5. **意外把服务暴露到局域网/公网**：默认 `127.0.0.1`；`0.0.0.0` 必须显式 `--allow-lan`；公网只通过隧道/HTTPS；错误配置必须拒绝启动。
